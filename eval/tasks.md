# Eval: задачи e2e-прогона агента

Правила прогона: формулировка задачи копируется агенту дословно (`npm run agent -- "..."`),
без подсказок. «Мок» — что настроить интерсептом в `nitro3:serve` до запуска приложения.
«Приёмка» — для человека на стенде. Метрики по задаче: итераций до зелёного валидатора;
поднялось без ошибок консоли; пункты приёмки; токены/время.

Классификация каждого фейла: (а) дыра в схеме → патч схемы; (б) незнание поведения →
правило/пример; (в) выдуманное поле/событие → семантическая проверка или пример;
(г) слабость модели/промпта → системный промпт, модель.

Порог гипотезы первого прогона: ≥7/9 поднимаются, ≥5/9 проходят приёмку без ручных правок.

---

## T1 — простые (без dataSources)

**1. Калькулятор чаевых.**
Задача: «Сделай калькулятор чаевых: поле для суммы счёта, три кнопки процента
(10/15/20), ниже — сумма чаевых и итого. Активный процент должен быть виден.»
Приёмка: ввод суммы пересчитывает; кнопки переключают процент и это видно;
пустое/нечисловое поле не ломает приложение.

**2. Чек-лист смены.**
Задача: «Чек-лист открытия смены из 5 пунктов-переключателей, счётчик
"Выполнено X из 5" и бейдж "Готово", когда выполнены все.»
Приёмка: клики переключают туда-обратно; счётчик верный; бейдж появляется
на 5/5 и исчезает при снятии пункта.

**3. Секундомер.**
Задача: «Секундомер: крупные цифры прошедшего времени, кнопки Старт/Стоп/Сброс.
Недоступные в текущем состоянии кнопки должны быть заблокированы.»
Приёмка: идёт после старта; стоп замирает; сброс обнуляет; disabled-логика верная.

## T2 — средние (dataSources + роутинг)

**4. Карточка клиента по ID.**
Задача: «Экран поиска клиента: поле ID и кнопка Найти. По клику грузим клиента
из POST /demo/api/client/get, показываем имя, почту и статус бейджем. Пока грузится —
лоадер. Ошибка 400 — алерт с текстом из ответа, прочие ошибки — алерт со статусом.»
Мок: успех `{name, email, status}` с задержкой 800мс; вариант 400 `{errorMessage,
errorDetails}`; вариант 500.
Приёмка: успех рисует поля; лоадер виден; оба типа ошибок дают правильные алерты.

**5. Список заявок.**
Задача: «Список заявок: грузится сам при открытии из POST /demo/api/tickets/list,
каждая заявка — карточка с номером, темой и бейджем статуса. Кнопка Обновить.
Если заявок нет — надпись "Нет заявок".»
Мок: `{list: [{id, subject, status} x5]}`; вариант пустого списка.
Приёмка: авто-загрузка; карточки через дочерний компонент; Обновить перезапрашивает;
пустой ответ показывает заглушку.

**6. Мини-навигация.**
Задача: «Приложение из трёх экранов — Дашборд, Заявки, Настройки — с верхним меню.
Дашборд открывается по умолчанию, текущий путь показан в шапке, заголовок вкладки
браузера — "Рабочее место".»
Приёмка: переходы по ссылкам; defaultRoute — Дашборд; путь в шапке меняется;
title вкладки установлен.

## T3 — сложные

**7. Мастер-детейл сотрудников.**
Задача: «Слева список сотрудников (грузится при открытии из POST /demo/api/staff/list),
клик по сотруднику грузит его детали из POST /demo/api/staff/get и показывает справа:
имя, должность, отдел, почта. На деталях лоадер, ошибки — алертом.»
Мок: список 6 человек; детали по id с задержкой 500мс; вариант ошибки на одном id.
Приёмка: клик грузит детали именно выбранного; быстрые повторные клики не путают
данные; ошибка детали не ломает список.

**8. Поиск с фильтром.**
Задача: «Поиск по заявкам: строка запроса, выпадающий фильтр статуса
(Все/Открыта/Закрыта), кнопка Искать. Запрос уходит в POST /demo/api/tickets/search
с текстом и статусом, результаты — списком, сверху счётчик "Найдено: N".
Если пусто — "Ничего не найдено".»
Мок: возвращать разные наборы по статусу (проверяем, что параметры реально уходят —
смотрим payload в интерсепте).
Приёмка: payload содержит текст и статус; фильтр меняет результаты; счётчик верный;
пустой результат — заглушка.

**9. Дашборд смены.**
Задача: «Дашборд смены оператора: сверху таймер времени смены, стартующий сам
при открытии; сетка из трёх плиток-метрик (В очереди / В работе / Закрыто за смену),
кнопка "Обновить сводку" грузит цифры из POST /demo/api/shift/summary; бейдж статуса
смены. Тёмных тем не нужно, аккуратная сетка.»
Мок: `{queued, inProgress, closed, status}` с меняющимися цифрами.
Приёмка: таймер тикает сразу (mode onLoad); обновление меняет плитки; сетка не едет.
