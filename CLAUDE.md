# nitro3-ai — прототип AI-генерации конфигов Нитро3

Гипотеза: агент + эталонные примеры + валидатор = рабочий конфиг Нитро3
по текстовому описанию. Гипотеза ПОДТВЕРЖДЕНА на 3 промптах без сети:
секундомер, калькулятор чаевых и чек-лист собраны агентом и работают на превью
редактора (чек-лист — после фикса not→$not; этот класс теперь ловит валидатор).

## Команды
- `npm run validate` — все эталоны + канон (обязательно перед коммитом)
- `npm run agent -- "описание" --trace` — генерация (env: LLM_PROXY_URL,
  LLM_PROXY_TOKEN, NITRO_MODEL); --trace пишет полный messages в out/trace.json

## Источники истины (по приоритету)
1. `schema/configSchema.json` — структура. Всё структурное — сюда, не в правила.
2. `README.md`, «Правила» — только поведение, невыразимое схемой.
3. `examples/*.yaml` — эталоны. `canonical/nitro-editor.yaml` — не редактировать.

## Договорённости
- Изменил примеры/схему/валидатор → `npm run validate` до коммита.
- Поля и события не выдумываем: нет в схеме и примерах → сначала подтверждение
  на стенде, потом в пакет.
- Фейл прогона классифицируем — схема / правило-пример / семантическая проверка /
  промпт-модель — и закрываем патчем.
- Не наращивать инструментарий заранее: следующий шаг добавляется, только когда
  в него упёрлись на текущем.

## Состояние контура

Валидатор v0.6: пер-узловая структурная диагностика по веткам типов
(несуществующие типы называются по имени с палитрой), реестры событий и экшенов,
AST-проверки JSONata (несуществующие функции, голые вызовы без $, поток данных,
.length-линт; имена внутри предикатов фильтров не считаются источниками),
обход contentEnd, кросс-коллизии id (примитив/модель/dataSource/сервис).
Схема v0.3 (payload обязателен у экшена, interval таймера >= 1000).
Модели: gpt-5.x через OpenRouter — рабочий контур; qwen3-80b доходит не всегда.
Эталонов 13: №13 — переключатели кнопками (булев вариант чек-листа, инверсия
через $merge + $not).
