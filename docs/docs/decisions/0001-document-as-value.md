# 0001. Документ конфига — JSON-значение, не развёрнутые объекты

Статус: accepted. Дата: 2026-09-01. Задача: <эпик навигационной панели>.

## Контекст

Studio держит конфиг Nitro3 в памяти, показывает его структуру и будет править. От
внутреннего представления зависят round-trip, идентичность узлов и канал правок.

## Варианты

1. **JSON-значение + чистые функции** (селекторы / команды / диагностика); индексы —
   `computed`-кэш от значения → дисциплина ролей вместо привычной объектной навигации.
2. Развёрнутые типизированные объекты (`PanelNode` и т. п.) → round-trip доказывается на
   каждом типе поля; неизвестные ключи (`serverSide`, `comment`) теряются или тащат JSON
   внутрь классов; идентичность по ссылкам протухает при замене поддерева; JSON Patch
   требует конвертации в обе стороны; новый тип в схеме блокирует открытие файла.
3. Нормализованные таблицы и индексы → O(1)-поиски и лёгкие каскады, но два представления
   и класс ошибок синхронизации; конфиги воркспейса малы — цена не окупается.

## Решение

Вариант 1 с дополнением из третьего: индексы существуют, но только как `computed` от
значения. Главный довод: `export(open(x)) === x` и единственный канал правок (команда →
JSON Patch) верны по построению, а не по тестам.

## Последствия

Дешевле: сквозной проход неизвестных ключей; undo как стек обратных патчей; агентский и
пользовательский каналы правок совпадают. Дороже: нет типизированной навигации из коробки —
компенсируется типами из схемы и type guard'ами. Запрещено: мутация значения; классы-обёртки
над документом; второе представление как источник истины.
