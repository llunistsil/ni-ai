Реализуй задачу по спеке `docs/changes/<KEY>/tasks/<slug>.md`.
(Одиночное изменение без нарезки — по `intent.md` и `plan.md` той же папки.)

Правила:
- Порядок работ — из плана и спеки, не свой. После каждого шага — `npm run verify`,
  хвост вывода — в отчёт и в MR.
- Трогай только файлы зоны ответственности своей задачи (plan.md, «Зоны ответственности»).
  Понадобился чужой файл — остановись и доложи: это ошибка нарезки, а не повод править.
- Отклонился от плана или спеки — правь соответствующий файл в том же коммите.
  Отклонение ломает контракт параллельной задачи — стоп и отдельный документный MR.
- Багфикс: сначала минимальный падающий тест, коммит, затем исправление. Тест не
  ослаблять и не удалять.
- Линт не ослаблять: ни severity, ни ignore, ни порогов. Точечный
  `eslint-disable-next-line <rule> -- <причина>` — единственная форма, упомяни в MR.
- Развилка по тесту `docs/decisions/README.md`: блокирует — стоп, черновик ADR proposed
  с вариантами и твоей рекомендацией; не блокирует — самый обратимый вариант плюс абзац
  в MR.
- Ветка `feature/<KEY>`, коммиты conventional. Красный verify после твоего изменения —
  чини amend'ом текущего коммита, не цепочкой fixup'ов.
- «Готово» = раздел «Готово, когда» спеки выполнен построчно; приложи этот чек-лист
  с отметками в MR.
