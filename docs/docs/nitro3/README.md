# Nitro3 — справочник для Studio

Не справочник платформы целиком: только то, что Studio должна знать о конфигах Nitro3,
чтобы их строить, проверять и не ломать при редактировании.

Приоритет источников при конфликте: **рантайм** (комментарии примеров, боевой конфиг) →
`schema/nitro3-schema.json` → прозаические доки платформы. Схема местами неполна, доки
местами устарели. Последняя сверка с рантаймом — 2026-08-18 (schema v2).

| Файл | Что | Кто потребляет в Studio |
|---|---|---|
| `schema/nitro3-schema.json` | JSON Schema v2 — единственный источник допустимых сущностей и полей | валидатор; формы инспектора строятся из неё |
| `catalog.json` | рантайм-контракт сущностей: inputs / outputs / actions — то, чего в схеме нет | редактор биндингов (автодополнение триггеров и actions), инспектор |
| `model.md` | модель конфига: сущности, идентификаторы, ссылки, области видимости | ядро: `ConfigDocument`, индексы, `RenameId`, резолвер ссылок |
| `bindings.md` | семантика биндингов и трансформеров, допустимый JSONata | `SetExpression`, резолвер, `diagnose` |
| `rules.md` | правила диагностики: id, условие, текст исправления, автофикс | `diagnose`, фикстуры `*.expected.json`, evals |
| `examples/` + `examples.md` | 19 эталонных конфигов и индекс — что каждый показывает | фикстуры round-trip; референс для агента при генерации |

## Правила работы с каталогом

- **Нет в схеме — не существует.** Поле или сущность «из доков, но не из схемы» не попадает
  в инспектор и помечено в `catalog.json` статусом `unverified`.
- **Неизвестные ключи сохраняются байт-в-байт.** `serverSide`-инструкции, `comment` и всё,
  чего Studio не знает, проходят сквозь редактор без изменений. Studio их не показывает и не
  правит.
- **JSON — формат ядра.** Примеры лежат в YAML только для чтения человеком; фикстуры для
  тестов конвертируются из них при сборке `libs/nitro3-contract`.
- **Язык — русский**, как у исходных доков платформы. Не переводить.
- Схема и примеры переезжают в `libs/nitro3-contract` вместе с созданием библиотеки, одним
  `git mv`. До тех пор живут здесь.

## Что сознательно выброшено из исходных доков

Чек-лист генерации YAML для LLM, советы по оформлению стилями Taiga, описание устаревших
форм (`engine: JSONAta`, `iframe.src`) как рабочих — в Studio это либо не нужно, либо
превращено в правила нормализации при импорте (`rules.md`, раздел «Импорт»).
